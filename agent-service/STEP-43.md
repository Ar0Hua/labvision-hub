# Step 43：图片组受控视觉差异分析

## 对应文档

- P0 / FR-04：比较图片组中的对象、场景、构图、清晰度和文字等可观察差异。
- 阶段 5：视觉分析必须限制单批图片数和视觉 token，并与确定性元数据证据分开展示。

## 本步完成

- 图片组确定性元数据对比完成后，可继续调用现有 DashScope/Qwen 视觉适配器生成可观察差异。
- 视觉输入仍由 Java 在当前任务和用户权限下重新校验，并仅签发短期 HTTPS 缩略图 URL。
- 运行器在请求 Java 视觉输入前按 `AGENT_MAX_VISION_PICTURES` 和硬上限 8 截断，不再请求超过模型实际消费量的临时 URL。
- 回答标题明确显示“覆盖 X/Y 张”，其中 X 是本次模型实际收到的图片数，Y 是图片组引用总数。
- 元数据事实和“视觉模型观察”分段展示；视觉输出继续禁止推断实验因果、模型优劣或不可见科研事实。
- 视觉模型未配置、调用失败或没有合法输入时，保留第 42 步确定性结果，不让整个图片组任务失败。
- 若模型文本引用本批未提供的 pictureId，丢弃该视觉观察，禁止组外引用进入答案。
- SSE 分别记录 `picture_group_analysis` 与 `vision_analysis` 工具事件及各自处理数量。

## 边界

- 当前是单批视觉比较，最多 8 张且默认配置为 4 张；超过上限时通过覆盖率提示明确披露抽样范围。
- 20 张级完整覆盖需要后续 map-reduce 分批分析和汇总，不能把本步描述为已完成大组分析。
- 本步不生成向量相似度矩阵、聚类、重复组或视觉异常分数。
- 本步没有连接真实 DashScope、COS 或数据库。
