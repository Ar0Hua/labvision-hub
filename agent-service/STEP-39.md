# Step 39：结果级多轮检索操作

## 对应文档

- P0 / FR-02：连续追问中引用上一轮结果，支持排除指定结果和以指定结果继续相似检索。
- 阶段 4：多轮状态必须按用户与会话隔离，引用图片在使用时重新校验当前权限。

## 本步完成

- `SearchIntent` 增加最多 5 个示例图片 ID 和最多 20 个排除图片 ID，统一执行 Long 范围、去重和未知字段拒绝。
- 千问输入增加上一轮实际返回的有序图片 ID；“第 N 张”只能映射到该列表对应位置，提示词明确禁止编造 ID。
- LangGraph 从 checkpoint 中读取上一轮引用结果，并与已验证的结构化检索条件一起传给本轮意图解析器。
- “更像第 N 张”复用 `image_dense` 召回；示例图在查询 Qdrant 前再次通过 Java 校验当前用户权限，权限失效时不执行该图的向量查询。
- “排除第 N 张”写入 Qdrant `must_not`，同时在关键词候选与最终融合结果中再次过滤，避免各召回通道重新带回排除项。
- 首轮由前端显式选择的平台图片仍优先写入本轮意图状态，可在后续追问中继续安全引用。
- checkpoint 仅保存图片 ID 和类型化意图，不保存临时 URL、令牌或图片内容；所有返回候选仍由 Java 重新鉴权。

## 边界

- 本步支持基于上一轮返回顺序的排除与相似检索，不支持自然语言修改图片元数据。
- 本步不实现“相关/不相关”显式反馈训练、跨会话长期偏好或相似度阈值在线学习。
- 模型不可用时会保留上一轮合法结构化状态，但不会凭规则猜测“第 N 张”的操作语义。

## 验证

- 第 39 步未修改 Java 或前端，沿用 Step 37 的 Java Agent 43 项测试与 Step 36 的前端生产构建结果。
